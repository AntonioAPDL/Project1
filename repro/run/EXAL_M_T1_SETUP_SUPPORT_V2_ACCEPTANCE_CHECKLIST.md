# exAL-M-T1 Setup/Support v2 Acceptance Checklist

Date: 2026-05-07

## Purpose

This checklist defines the conditions that must be satisfied before we trust the corrected `v2` cutoff-specific setup/support figure family and use it to update the revised article.

Use this as the implementation gate.

## Gate 0: Provenance freeze

Before any rendering is trusted, confirm:

- the cutoff appears in `EXAL_M_T1_SETUP_SUPPORT_V2_SOURCE_MANIFEST.md`
- the selected model run root is the verified CRPS-linked `exAL-M-T1` run
- the figure bundle root is the authoritative forecats/histfix bundle for that cutoff

## Gate 2: Policy fidelity

### Short-window cutoffs must show

- NWS primary retrospective lane = `nws_synth_retro_ens_mean`
- correct GloFAS historical source for the cutoff window
- gapfix/fill metadata when present

### Histfix cutoffs must show

- GloFAS source = `glofas_hist_v31_lisflood_cons`
- NWS early support = `nws_retro_v21`
- NWS cutoff-era tail = `nws_retro_v30`

### Required evidence files

At least one of:
- bundle `meta.yaml`
- `retros_source_lineage.csv`
- `policy_summary.yaml` generated by the `v2` workflow

## Gate 3: Window correctness

### `usgs.png`

Must satisfy:
- start date equals the actual retrospective support start used by the model fit
- end date equals `cutoff_date`
- not a forecast-window plot

### `precip_soilmoisture_climatePC1_faceted_labeled.png`

Must satisfy:
- same historical support span as the retrospective fit support
- not silently truncated by merged model matrices

### `retrospective_log_discharge_plot_faceted.png`

Must satisfy:
- same historical support span as the retrospective fit support
- no hard-coded y-limits

### `forecats.png`

Must satisfy:
- plot window matches bundle metadata:
  - `plot_start`
  - `plot_end`
  - `forecast_start_date`

## Gate 4: Source-layer correctness

### Must be true

- `usgs.png` is rendered from `usgs_daily.csv`
- covariate figure is rendered from raw covariate CSVs
- retrospective figure is rendered from lineage/bundle retrospective files
- `forecats.png` is rendered from bundle-native weighted/member forecast files

### Must not be true

- figure built from `X`
- figure built from `Y`
- figure built from `timestamps`
- figure built from merged `all_data` as the canonical plotting surface

## Gate 6: Article mirror contract

For the mirrored article-side family, require:

- `generated/setup_support_by_cutoff_v2/<slug>/...`
- `generated/setup_support_by_cutoff_v2_review/SETUP_SUPPORT_BY_CUTOFF_V2_REVIEW.md`
- `generated/setup_support_by_cutoff_v2_review/gallery.html`
- `generated/setup_support_by_cutoff_v2_review/figure_manifest.csv`

And confirm:
- article-side hashes match runtime-side hashes
- manifest rows = `20` for the five-cutoff, four-figure family

## Gate 7: Visual QA

### Minimum visual checks per cutoff

1. `usgs.png`
- no suspicious early truncation beyond the true support start
- subtitle explicitly matches the real support window

2. covariate figure
- curves extend across the intended support span
- no obvious clipping
- no spurious narrowing caused by merged data windows

3. retrospective figure
- NWS and GloFAS traces visibly follow the expected versioning logic
- no flat or clipped appearance from fixed y-limits

4. `forecats.png`
- cutoff marker is correct
- forecast start date is correct
- before-cutoff retrospective context is plausible
- after-cutoff forecast ensemble window is correct

## Gate 8: Cross-check against published model provenance

For each cutoff, confirm all of the following:

- selected model run root matches the published `exAL-M-T1` row
- figure bundle root matches the canonical source manifest
- no figure pulls forecast or retrospective data from another cutoff
- no figure pulls fallback replay-only metadata when authoritative bundle metadata exists

## Gate 9: Documentation update gate

Only after `v2` passes the gates above:

- update `CANONICAL_REVISED_ARTICLE_WORKFLOW.md`
- update `EXAL_M_T1_SETUP_SUPPORT_BY_CUTOFF_WORKFLOW.md`
- update article-side provenance docs
- update article-side refresh helpers
- mark the old `v1` family as superseded

## Final go/no-go rule

The corrected `v2` family is allowed to replace the current article-side setup/support figure family only if:

1. the canonical source manifest is satisfied for all five cutoffs,
2. all four figures per cutoff are rendered from the correct source layer,
3. the versioning policy is explicit and correct,
4. the article-side mirrored bundle matches the runtime-side bundle,
5. visual QA is complete,
6. and the updated provenance docs are in place.

If any of those fail, the figure family is still in audit status and should not be treated as the final article-ready update.
