DECISION
--------
The content-reduction plan is implementable from saved material. Its main missing
prerequisite is an explicit two-document reading-package contract. Establish that
contract and test its fixtures BEFORE moving appendix assets, rather than leaving
two-root validation to the former Stage 6. Otherwise the existing single-root
checks will fail valid moves and, in a few places, pass checks on unused material.
This infrastructure is small but necessary. Do not redesign statistical generators
or loosen source-value comparisons to make the editorial split pass.

1. RECOMMENDED DOCUMENT ARCHITECTURE
----------------------------------
Keep wileyNJD-APA.tex as the main root, preserving the existing Overleaf default.
Add supporting_information.tex as a second independent root in the SAME repository.
Both compile from repository root. The SI is not input into the main document.
Use the current Wiley class in each document initially, avoiding simultaneous
layout changes. Keep journal layout changes separate from the content decision.
Each root has its own title/front matter, local labels, bibliography invocation and
output job. Use the existing wileyNJD-APA.bib in both documents: each BibTeX job
selects its own cited entries, which supplies independent reference lists without
duplicating and desynchronizing bibliographic records.

Use explicit independent SI counter formatting: S1, S2, ... for sections, tables,
figures, equations and algorithms as appropriate; SI page numbers may be S1, S2,
... if the chosen class handles them cleanly. Keep numerical cross-references
local. Do not extend the existing A/B/C/D appendix counter resets mechanically.
Check hyperref destinations/algorithm counter behavior in the first SI proof.

Minimal source organization is preferable: two roots and their actual table
fragments are sufficient. Split technical sections into shared-root-relative
input files only when useful for maintainability. If common preamble definitions
are extracted, use a small braced input file tracked by the dependency collector.
Do not build one large conditional root with hidden main/SI modes: the current
static include parser cannot interpret conditional TeX branches reliably.

Cross-document references: prefer descriptive references such as "Supporting
Information, Numerical details of predictive synthesis" or a named table/section.
These are readable and independent of the other document's auxiliary files.
Use ordinary ref/eqref only within its own document. No xr/externaldocument import
of a locally existing main.aux or SI.aux; no requirement to build the other paper
first; no checked-in stale aux files. If exact cross-document S-numbers prove
necessary, introduce a small explicit reference registry, then validate each entry
against the compiled labels in both fresh builds. Do not hide cross-document refs
behind unvalidated hardcoded numbers or shell-escape generation.

Overleaf needs one selected main root at a time. Keep its default as
wileyNJD-APA.tex; selecting supporting_information.tex should independently build
SI. Document this operation and export two PDFs. Do not introduce a custom
latexmkrc that secretly compiles a second root on every main-paper compile.
No claim that a GitHub push automatically changes the selected Overleaf root.
