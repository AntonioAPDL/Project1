Recommended final architecture

1. Introduction: task and uncertainty; information roles; focused background;
   scientific contributions; application and roadmap.
2. Forecasting setting and data: a short target/source-role description, units,
   extraction/alignment and forecast-origin context. Detailed inventories belong
   in support, not in a long new opening section.
3. Bayesian correction and predictive synthesis: brief likelihood interpretation;
   one scientific state-space formulation; concise prior structure; actual VB
   workflow; predictive synthesis across fitted quantiles.
4. Application specification and evaluation methods: component motivations and
   features, numerical settings, origins/horizons, comparison variants and scores.
5. Results: an explicitly illustrative reference forecast, comparisons, quantile
   results and supporting interpretation. Introduce the reference specification
   before displaying it. Preserve authoritative numerical conclusions.
6. Discussion and conclusions: connect the task and presented evidence, clarify
   practical interpretation, and avoid repeating coefficients and captions.

plus supporting panels and summaries as needed. The move map preserves current

Safe operations and command constraints

The preparation auditor is executable now. It writes one requested new JSON file
under /tmp or this readiness directory, refuses overwrites, hashes narrow selected
inputs, and performs no rendering, fitting, refresh, network or Git write action.
Use the command in README.txt. Its source/workflow logical identities support
comparisons across separate worktree paths; explicit response/public roots can be
supplied when those repositories remain outside the review workspace.

Future render commands are conditional on completing staged-path verification.
scripts/render_publication_post_figures.R --run-dir takes the directory containing
figure_manifest.csv, not a top-level model run. Its default rewrites source PNGs.
The lower-level focus renderer also writes style/manifests and is not a read-only
probe. Copy/rebase mutable manifest paths, stage post/cache and post/inputs, and run
from the isolated workflow so it loads the edited helper rather than live code.
Never symlink a mutable manifest/output directory back into an authoritative run.

For the context renderer, verified flags are --project-root, --config, --output-root
and --slugs. Use config/exal_m_t1_setup_support_by_cutoff_v2_20260516.json, an isolated
output root and one representative slug first. --clean is unnecessary for a fresh
proof directory. The specific univariate support helper has --univar-only and
--article-root/--workflow-root arguments; it is still a mutation and should operate
on the staged article only.

The broad sync shell wrapper describes its default as non-mutating but invokes

Use narrow checks first. No broad refresh, cleanup, historical replay or poster

The fresh build also verified a local toolchain detail: use the article directory
for LaTeX so the real installed siunitx is loaded rather than the workflow-root
fallback. With output under /tmp, BibTeX must run from that build directory with
BIBINPUTS and BSTINPUTS pointing to the article source. Passing an absolute /tmp
basename to BibTeX from the article directory is rejected by openout_any=p.
Keep this execution pattern in the future isolated build recipe.

compact artifacts; do not copy the runtime archive or load full fit objects. The
baseline audit hashed about 61 MiB and required no model execution. Use a small
review-space budget and recheck free disk before each family render.
