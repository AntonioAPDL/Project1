### 2. The final forecasted USGS object is **not** computed as “forecasted GloFAS quantile minus discrepancy quantile”.
The actual path is:
1. `smoke_project_state_gaussian()` projects the full posterior state into a USGS latent forecast location using `FF_list` weights.
2. In keep mode, `smoke_build_usgs_projection_weights()` explicitly includes the transfer/discrepancy state weight (`zeta_idx`) when `use_covariates` is on.
3. For each quantile row, `exdqlm::rexal()` generates predictive draws using that projected location plus sampled `sigma` and `gamma`.
4. `synthesize_samples()` then fuses the seven quantile-specific predictive draw arrays into a synthesized USGS forecast sample matrix.
5. The quantile CSV is computed **from that synthesized forecast sample matrix**, not from a direct quantile subtraction.

Relevant code:
- Forecast synthesis build:
  - `R/environmetrics/40_figures_smoke_fast.R:624`
  - `R/environmetrics/40_figures_smoke_fast.R:708`
  - `R/environmetrics/40_figures_smoke_fast.R:739`
  - `R/environmetrics/40_figures_smoke_fast.R:766`
- Keep-mode transfer/discrepancy projection weight:
  - `R/environmetrics/40_figures_smoke_fast.R:451`
  - `R/environmetrics/40_figures_smoke_fast.R:479`
- Bundle emission and quantile CSV write:
  - `R/environmetrics/40_figures_smoke_fast.R:2372`
  - `R/environmetrics/40_figures_smoke_fast.R:2385`

Conclusion:
- The shorthand “forecasted GloFAS quantile minus discrepancy component” is only **partially** directionally right.
- In the current implementation, discrepancy enters upstream as part of the latent state projection, not as a direct subtraction of already-formed forecast quantiles.

Key change in ranges:
- Current `q95` forecast max: `4.81835e+12`
- Corrected `q95` forecast max: `3.24077`
- Current `q80` forecast max: `4.44063e+10`
- Corrected `q80` forecast max: `1.67319`
- Current `q50` forecast range: `3.59811` to `8.27559`
- Corrected `q50` forecast range: `-1.15689` to `0.912525`

This confirms the current cached “log1p” forecast outputs were being inflated by an extra transform.

### 6. The transform fix does **not** fully solve the scientific problem.
The corrected forecast-window quantiles are no longer astronomical, but the predictive distribution is still unhealthy:
- Corrected `q05` forecast range: `-27.7432` to `-17.1209`
- Corrected predictive mean range: `-3.85445` to `-2.07939`

These values are negative on a quantity being labeled as `log1p(cms)`.
That is not physically interpretable for nonnegative river flow.

So the current evidence supports two separate conclusions:
1. there was a real post-stage scale-transform bug, and
2. even after removing that bug, the representative forecast synthesis is still scientifically unhealthy.
